# QUESTIONS (small technical choices I made myself)

| # | Choice | Reason |
|---|---|---|
| 1 | Monorepo: `backend/`, `app/`, `landing/`, `docs/` | One PR per phase covers all parts |
| 2 | Students and staff share the `users` table with a `role` column (student, super_admin, payments_helper, content_checker) | One auth system; Nova uses the same table |
| 3 | Student ID format `ST-XXXXX`, alphabet without 0/O/1/I/L (31 chars → 28.6 million IDs) | Easy to read aloud and type on WhatsApp |
| 4 | Install ID (random UUID made by the app) is stored only as a SHA-256 hash | Less sensitive data in the database |
| 5 | Sanctum personal access tokens, one per install; re-registering the same install revokes the old token | Simple, works offline-first |
| 6 | Google ID tokens verified offline against Google's JWKS (cached 1 h), audiences from `GOOGLE_CLIENT_IDS` | No extra Google SDK on the server |
| 7 | Google sign-in on a new phone moves that phone's attempts, bookmarks, devices **and Premium grants** into the existing account, then deletes the anonymous account | Nothing paid or studied is lost |
| 8 | Fill-in and numeric are two technical types (`fill_in`, `numeric`) for the one "fill-in / numeric" type in the brief → 9 enum values for the 8 brief types | Numeric needs tolerance and units |
| 9 | Answer keys travel with the content (needed for instant offline feedback); the server re-scores every uploaded answer and never trusts the phone's result | Offline-first + anti-cheat |
| 10 | Answers faster than 800 ms are flagged `too_fast`; time per answer capped at 10 min (both editable settings) | Anti-cheat signals for the leaderboard (Phase 4) |
| 11 | Question `version` goes up when a student-visible question's stem, key, explanation, media, passage or options change | Re-scoring after a fix (Phase 2/3) knows which version was answered |
| 12 | Sync uses an append-only `content_changes` table as the cursor | Works on shared hosting, no extra services |
| 13 | Larastan level 8 (level max needs typed request DTOs everywhere — planned refactor, not needed for safety) | Strict but practical |
| 14 | PHP 8.2 minimum (CI tests 8.2 and 8.3) | Shared hosting compatibility |
| 15 | Nova code lives in `backend/nova/` (namespace `App\Nova`), loaded only when `laravel/nova` is installed | Install, CI and tests never need the licence |
| 16 | Premium plan lengths: term 120 days, year 365 days (editable settings) | Ethiopian school term ≈ 4 months |
| 17 | A new Premium grant starts when the current one ends (stacking) | Students never lose paid days |
| 18 | App uses the `material_ui` package (Flutter 3.50 moved Material widgets out of the SDK; `flutter/material` is deprecated) | No deprecation warnings |
| 19 | Region stored as a code (`somali`, `addis_ababa`, …): Ethiopia's 12 regions + 2 chartered cities (2023 list). Somali is first | Labels can be translated later; focus region is one tap away |
| 20 | Stream question only for Grades 11–12; "retaking the exam" question only for Grade 12 | Streams start in Grade 11; only Grade 12 sit the national exam |
| 21 | The 5-question warm-up in onboarding is bundled and stays on the phone (never uploaded) | Works offline on first start; no fake question IDs on the server |
| 22 | Free students download a chapter when they first open it (needs internet once); whole-subject packs stay Premium | Matches DECISIONS #11 (confirmed by owner) |
| 23 | Practice sets: Quick 10 = up to half "last answer wrong" + new questions; Mixed 20; chapter/unit up to 30; Quick revise 5; Timed = 60 s per question | Spaced repetition proper comes in Phase 3 |
| 24 | Practice shows right/wrong and the explanation straight after "Check" | Learning mode; exams (Phase 3) show results only at the end |
| 25 | Ordering questions never start in the right order; items move by drag **or** up/down buttons | Fair question; works with screen readers and small screens |
| 26 | Theme (phone / light / dark) is saved on the phone only | Not personal data, no need to sync |
| 27 | Android: minSdk 24 (Android 7.0), internet permission only, app-data backup off | Old phones supported; token never leaves the phone |
| 28 | Noto Sans is subset to Latin + Greek + common symbols (−1.1 MB). Ethiopic fonts come with the Amharic UI | Smaller download for students on mobile data |
| 29 | Golden (screenshot) tests use the real fonts and a pinned Flutter (3.50.1) in CI | Pixel comparisons stay stable |
| 30 | Reminder time is saved in the profile now; the daily reminder notification (WorkManager, inexact) is built in Phase 4 | Phase 4 = engagement |
| 31 | The router re-checks redirects only when "onboarded" or the minimum build changes | A test found that refreshing on every profile edit undid the "Save" screen close |
| 32 | Answer letters inside a chapter file may follow a pattern (a reviewer noticed A, B, C, D runs). They are kept: the app always shuffles question order in practice, and fixed mocks mix chapters and will be checked so their answer keys show no runs | Re-lettering 2,400 checked questions would void their second solves for no student-visible gain |
| 33 | Summary PDFs are free for everyone — owner confirmed (DECISIONS #15) | They spread on Telegram and carry only the price-free landing link |
| 34 | Fixed mocks — owner confirmed (DECISIONS #16): 3 per subject × 50 choice questions, 1.5 min per question (75 min), mocks 1–2 free, 3 Premium; Aptitude has 2 (its bank has 103 choice questions). `make-mocks.py --size --mocks --free --minutes-per-question` remakes them | Real paper sizes and times are not published by EAES |
| 35 | Streak, XP and badges are worked out **on the phone** from saved answers (nothing new sent). A day counts for the streak at **10 answers**; XP = 10 per right answer, 2 per wrong answer, 50 per finished exam; the week starts on Monday; 10 badges (10/100/1,000 answers, 3/7/30-day streaks, first exam, 80%+ exam, 1 and 10 strong chapters). Owner may change the numbers | Simple, motivating, no extra student data |
| 36 | Daily reminder = one-off WorkManager task at the reminder time, re-planned after each run (inexact, no exact-alarm permission). It shows only if today's goal is not reached and only up to 3 hours after the set time. WorkManager's foreground-service permissions and service are removed from the manifest (never used). compileSdk is 37 (needed by flutter_local_notifications; targetSdk unchanged) with core library desugaring. Known build warning (not an error): Flutter says `flutter_tts` (since Phase 1) and now `workmanager_android` still use the Kotlin Gradle Plugin; it goes away when those plugins update | Play rules; honest note about a third-party warning we cannot fix in our code |
| 37 | Weekly leaderboard: top 50 by XP (same formula as the app) from server-scored attempts finished Monday 00:00–now, Addis Ababa time; only students who chose a nickname appear (opt-in), staff never; only rank, nickname, avatar and XP are sent. No region filter (it would reveal where students live). Staff can remove a bad nickname in Nova, which also removes that student from the board. The server now stores every attempt time in UTC even if a phone sends an offset | Privacy first; simple and fair |
| 38 | Daily challenge: 10 single-choice questions (no reading passages), the same for every student of one grade + stream on one Addis Ababa day, taking turns between their exam subjects. The list is saved the first time it is asked for, so new content does not change it during the day. Only the first try counts for "better than X% of today's players" (after 30 players, same setting as mocks); later tries are normal practice. A challenge from yesterday may still be uploaded (started before midnight). Grades without enough questions use Grade 12 subjects shared by both streams | Fair, same for everyone, works with offline uploads |
| 39 | Battles: two students answer the same 10 single-choice questions (60 s each) whenever they like; more right answers wins, a tie goes to the faster one; first try counts. "Quick battle" joins the oldest waiting battle of another student with the same grade + stream (or starts one); "Battle a friend" gives a 6-character code (no links, no contact details). Only nickname, avatar and scores are shown; no chat. A nickname is needed; battles end after 48 hours; at most 20 started per day | Social fun without any contact between students |
| 40 | Referral (**owner to confirm the reward**): each student has a 6-character invite code (separate from the private student ID). A new student can enter a friend's code within 7 days of first opening the app, once. It counts when the friend has 50 real (not too fast) answers within 14 days; the inviter then gets 7 Premium days, at most 4 a month. All five numbers are Nova settings; `referral_premium_days = 0` turns the Premium reward off. Sharing sends the code + the price-free `/app` link only | Rewards real studying, limits abuse, no payment text |
| 41 | Ads: one small 320×50 banner above the tabs (never on quiz, exam, challenge or battle screens: those open outside the tab shell), and a rewarded video that unlocks one more random mock today (max 2 a day; server counts them; the phone's word is trusted, so the cap is the limit — server-side ad verification can come later). Teen treatment, max rating G, non-personalised; no Privacy Sandbox topics/attribution. Premium (server or phone) never starts the ad SDK. Ad unit IDs via `--dart-define`, app ID via `key.properties`; defaults are Google's public test IDs. The ads library removes `RECEIVE_BOOT_COMPLETED`; the app re-adds it so reminders survive a restart | Play rules + teen audience; real IDs never in git |
| 42 | Explain more: Claude Haiku 5.5 (`claude-haiku-5-5`, $0.10/$0.50 per million tokens under 100K, Oct 2026) through the Messages API behind an `ExplanationProvider` interface. Premium only, 20 a day; each explanation is saved per question version and reused for everyone; new AI calls stop when the month's spending reaches `ai_monthly_cap_usd` ($20). No `ANTHROPIC_API_KEY` on the server = the button is hidden. Shown with "Written by AI. It may contain mistakes."; 3+ "not helpful" (more than helpful) hides it and a new one is made. A real AI call was not made (no key here); the request format is tested against a fake HTTP server | DECISIONS #4, tiny cost, honest labelling |
| 43 | App icon: an original cream "12" (Nunito Black, OFL) with an orange tick on teal, made by `app/tool/icon/make_icon.py` for every Android size, the adaptive icon and the 512 px Play icon. The script fails if the art leaves the 66 dp safe circle. **Owner may swap in a Kulmiss logo later**: replace the SVG mark and run the script again | Flutter's default icon would block the Play release |
| 44 | Store pack in `docs/store/` (listings, Data safety, App content, reviewer access, screenshots plan, feature graphic). Listing texts are checked in CI for Play's length limits and payment/ranking words. The user-typed region and city are declared as **approximate location**, so the privacy page and landing now say "no phone location (GPS)" instead of "no location" | Play's Data safety form counts a typed city as approximate location; the texts must not contradict the form |
| 45 | **Owner decision, recommended before launch:** students cannot yet report another student's nickname inside the app (staff can already remove one in Nova). Play's user-generated-content policy expects in-app reporting. Recommended: A) a "Report nickname" item on leaderboard and battle rows that adds it to the Nova reports queue; B) keep staff-only removal and the word filter; C) remove free nicknames and offer only a list of built-in names | A gives students a way to flag abuse with little work; C is the safest but less fun |
| 46 | **Resolved:** QUESTIONS #45 → option A (owner, 23 Nov): nickname reports are built in the Nova upgrade job (DECISIONS #33) | Owner answer |
| 47 | Nova custom pages (Branding with live preview) and the LaTeX/SVG question preview are plain JavaScript files loaded with `Nova::script`, using the Vue that Nova already provides (`window.Vue`). No extra build tools or npm packages in the backend | Nova 5 ships Vue globally; a build step would need Nova's private sources in CI |
| 48 | "Study minutes" on the dashboard are **estimated from answer times** the server already has (`attempt_answers.time_ms`), not sent from the phone | Minimum student data; the study plan stays on the phone (DECISIONS #24) |
| 49 | Dashboard range "This term" starts on the most recent 11 September or 1 February, or on the `term_starts_on` setting when that is later (an old setting is ignored next term) | Ethiopian school year starts in Meskerem; the second semester around February |
| 50 | Dashboard numbers are worked out every 10 minutes by `guul:stats` and read from the cache (cards may be up to 10 minutes old). "Active students" = opened the app (last visit, so no ↑/↓ comparison); the per-day chart counts students who answered questions that day. Partitions and lists show "now" (no range selector) | Fast pages on big tables; honest definitions |
| 51 | The Payments and Content dashboards are not locked with Nova's `canSee` (Nova crashes with an error 500 when another role calls a card's address); instead their menu links and every card check the role, so another role sees an empty page | Nova 5.7.6 behaviour, found by a test |
| 52 | Question preview in Nova: KaTeX 0.19.1 (MIT) is **self-hosted** in `backend/public/katex` (js, css, woff2 fonts only, 608 KB), not loaded from a CDN. The preview HTML is built on the server (`App\Support\QuestionPreview`, everything typed by staff escaped) and styled by its own small `resources/nova/guul-nova.css` with Nova's colour variables, because Nova's CSS only contains the Tailwind classes Nova itself uses (found in a real-browser check) | Works offline/behind firewalls, no third-party requests from the admin; light + dark mode |
| 53 | Nova lens "Incomplete content": a chapter is complete when students can see a summary, at least one solved exercise, at least one flashcard, the textbook link and **at least 30 questions** (today's content has 30 per chapter). | 54 | Nova lens "Missing explanation or diagram": an explanation shorter than 5 characters (like "B."), or question text with "diagram", "figure", "picture", "shown below", "graph below" or "the graph shows" while no picture is attached | Simple, explainable rule; finds the real gaps without reading every question |
| 55 | Each staff member's last filter per list is remembered **in their own browser** (localStorage, keyed by Nova user id), not on the server; "Reset Filters" forgets it. Checked in real Chrome: filter → leave → come back → same filter; reset → all rows | No new table or API; nothing about staff habits is stored on the server |
| 56 | Lens "Most active this week" counts answers since Monday 00:00 Addis Ababa time (the leaderboard week); "today" in lenses and filters is the Addis Ababa day | Same week and day as the leaderboard and the dashboard |
